## PPT 문구
검색으로 후보를 좁히고, 판단으로 메뉴 조합을 결정합니다.

E5는 사용자 질문과 메뉴 설명을 같은 의미 공간의 벡터로 변환하여, 전체 585개 메뉴 중 의미적으로 가까운 후보 80개를 검색합니다. 보완 검색으로 누락 가능성을 줄인 뒤, Decision Model(JEV)이 사용자 상황과 메뉴 간 보완성을 평가하여 최종 메뉴 조합을 선택합니다.

## 실제 실행

## 해석 주의
- 현재 로컬에서 검증한 개선판의 동작이다. 운영 API에 통합되었다는 뜻이 아니다.
- E5: intfloat/multilingual-e5-small, 384차원. 메뉴명·설명·선택 조건·별칭을 passage로, 사용자 입력을 query로 인코딩하고 정규화 벡터 간 코사인 유사도로 검색한다.
- 일반 설정은 원문 E5 Top-80을 유지하고, 표현 정규화 후 E5 Top-40 및 어휘 검색 Top-20에서 중복 제거한 최대 20개를 보완하여 총 최대 100개다. 이를 E5 Top-100이라고 부르면 부정확하다.
- JEV 1차는 후보별 Noul 적합도를 판단한다. 0.30 이상인 후보에서 0.7×적합도−0.3×이미 고른 메뉴와의 최대 코사인 유사도로 최대 10개를 고른다. 0.7은 적합도 하한이 아니라 MMR 가중치다. 10개가 적합도 내림차순과 같지는 않다.
- JEV 2차는 10개에서 3개씩 묶은 120개 조합과 none/unsure를 비교한다. 현재 코드는 충분한 후보가 있으면 3개 조합만 열거한다. 자유롭게 1~3개 수량을 결정하는 구현은 아니다.
- 최종 Choice confidence 하한은 없다. 이 사례는 set_2, confidence 0.27이다. 개별 Noul 값, 조합 confidence, 실측 평가 적중률 93%는 서로 다른 값이다. Noul 0.86을 검증된 정답 확률 86%라고 표현하지 않는다.
- 실제 최종 결제 메뉴는 ‘스타뱅킹 해외결제’이며 ‘해외 QR 결제’로 바꿔 쓰면 안 된다.
- UMAP은 실제 메뉴 임베딩의 고정 2D 투영이다. 단계마다 재배치하지 않는다. 점은 메뉴이며 입력 질문은 좌표를 임의로 만들지 않고 글로 표시했다. 서로 다른 필요를 담당하는 최종 메뉴는 떨어진 위치에 있을 수 있다. 실제 검색은 384차원에서 수행하며 UMAP 거리가 검색 순위·정답 신뢰도를 뜻하지 않는다.
