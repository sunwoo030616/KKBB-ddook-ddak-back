# 메뉴 유용성 기준으로 다시 검토한 100문항

**모델을 재실행한 성능 향상이 아니라 기존 응답의 평가 기준을 재검토한 결과다.** 원래 정답표·원시 결과는 수정하지 않았다. E5→JEV 개선판·LLM 단독·JEV 단독만 포함했다.

## 재검토 기준 · 사용자 수정 반영(v2)

- 직접 유효(D): 주어진 목표를 준비·확인·진행하는 데 직접 도움이 되는 실제 기능. 추천은 검토·준비를 뜻하며 자격·거래 성공을 확정하지 않는다.
- 조건부 유효(C): 대출 필요·숙소 선호·진행 단계 등 목표 적합성에 추가 확인이 필요한 기능. 알려지지 않은 계좌·카드·상품·통신서비스 보유 여부 자체는 감점하지 않는다.
- 목표 지원 부족·조건 위배(N): 다른 대상, 이미 완료한 업무, 목적의 변경, 중복 확인만 하는 기능.

직불카드 해외이용 설정, 리브모바일 로밍, 사업계좌 연결·관리, 연금 한도 조회는 알려지지 않은 보유·가입 여부만으로 감점하지 않도록 v1에서 D로 수정했다. 명시된 완료·제외 조건은 유지한다.

119개 상황/메뉴 공통 판정에 이유를 붙여 고정한 뒤 같은 판정을 세 모델의 모든 응답에 적용했다. 메뉴가 다른 모델에서 나왔다는 이유로 판정을 바꾸지 않았다. 단 상황이 다르면 명시된 조건에 따라 같은 메뉴도 판정이 달라진다. 예를 들어 여권 만료일 확인은 일반 여행 준비에는 D지만 이미 만료됐다고 말한 출장에서는 재발급을 대신하지 못하므로 N이다.

## 해석의 한계

- 제가 실제 메뉴 설명과 원문을 읽고 한 사후 재검토다. 독립 전문가 검수·실사용자 검증·완전한 블라인드 평가는 아니다. 관찰된 출력에 맞춰 평가범위를 확장했으므로 사전 고정된 벤치마크 정확도로 발표하면 안 된다.
- 100문항은 기존10상황×10표현이며 새로운100개 독립 상황이 아니다.
- 유용한 메뉴2개는 서로 다른 업무2개를 충족했다는 뜻이 아니다. 기차 조회와 기차 예매가 모두 유효해도 이동이라는 한 업무다. 따라서 95%를 복합업무 완수율로 부르면 안 된다.
- 기존의 필수 업무 Recall·정확한 전체조합 일치율은 이 새 판정에서 다시 정의하지 않았다. 유용한 추천이 필수 작업의 누락을 상쇄하지 않는다.
- LLM 단독은 추천0~8개(평균2.94개), 다른 두 모델은 항상3개다. 전체 응답을 유지한 주집계와 응답 앞의3개까지만 보는 보조집계를 함께 표시했다. 앞의3개는 보장된 관련도Top-3 순위가 아니며 개수를3개로 고정해 재실행한 결과도 아니다.
- LLM 단독은2개 미만을 추천한 문항이28개여서 2개 이상 기준에 구조적으로 불리하다. 추천 개수 제한을 통일한 새 실험 전에는 모델 자체의 추론 능력 우열로 단정하지 않는다.
- 조건부까지 포함한100%는 필요한 전제가 실제로 충족됐다는 의미가 아니다. 대표 성과 수치로 사용하지 않는다.
- 비용·시간은 기존 실측을 재사용했다. 이번에는 API를 호출하지 않았다. 실행 시점·동시성·캐시 조건이 달라 순수 모델 지연·비용만의 비교가 아니다.

## 판정 예시: 오사카 여행 S01_03

- E5 → JEV 개선판: 스타뱅킹 해외결제(직접 유효) / 환전신청(직접 유효) / KB손해보험 다이렉트 해외여행보험(직접 유효)
- LLM 단독: 환전신청(직접 유효) / KB손해보험 다이렉트 해외여행보험(직접 유효) / 트래블러스 체크카드(직접 유효) / 스타뱅킹 해외결제(직접 유효)
- JEV 단독 · 청킹: 환율조회(직접 유효) / 환율 계산기(직접 유효) / 직불카드 해외이용 등록·해제(직접 유효)
