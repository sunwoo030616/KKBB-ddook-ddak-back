# 후속 개발을 지원서·면접에 활용하는 방법

2026-11-04 개인 후속 개발이다. 2026년 9월 수상 당시 완성한 기능과 합쳐 수상 성과로 표현하지 않는다. 실제 결과와 제한은 [개발 보고서](ETRI_3_9_개발보고서.md), reports/의 원본 JSON에서 확인한다.

## K2027-03에 연결하는 설명

> 자연어 상황에서 필요한 금융 화면을 구성하는 서비스의 백엔드를 확장했습니다. 제한된 주제 안에서 모델이 검색어를 선택하고 검색 결과의 부족한 부분에 재검색을 수행하는 도구 실행 경로를 구현했습니다. 기관·기준일과 문서 ID는 서버에서 검증하고, 원문 근거와 자료 부족 상태를 실제 화면에 연결했습니다. 문서 추출 후보의 출처·해시·원문 위치를 기록하고 지식베이스 버전 복원을 추가했습니다. 별도 학술자료 메타데이터에서도 검색과 DOI 조회를 실행해 문헌 탐색으로의 적용 가능성을 확인했습니다.

이미 과학문헌 전문 지식을 갖췄거나 과학 파운데이션 모델을 학습했다고 말하지 않는다. 현재 과학문헌 실험은 Crossref 메타데이터이며, 본문 이해·메타 리뷰·인용 관계 분석까지 완성한 것이 아니다.

## K2027-09에 연결하는 설명

> 로컬 소형 LLM의 구조화 생성과 신경망 검색을 연결하고 추론 작업의 대기·검색·생성·데이터 바인딩 시간을 구분했습니다. 비동기 작업에 중복 제출 방지, 대기 예산과 용량 제한, SQLite 상태 보존·재시작 중단 처리를 적용했습니다. 동시 요청 수준별 응답시간·완료율·처리량을 측정하고 추가 모델 호출의 이득과 지연을 비교했습니다. 분산 학습 경험은 아직 없으며, 이 실험을 바탕으로 모델 서빙 시스템을 더 깊이 배우고 싶습니다.

MLX 라이브러리를 활용한 단일 Apple Silicon 장비의 개발이다. 자체 추론 엔진·이기종 가속기 최적화·대규모 분산 학습 성과로 부르지 않는다. 큐를 비동기로 만든 것과 모델의 병렬 추론은 구분한다.

## 금융권·대기업 백엔드 지원에서의 순서

1. D-Order의 직접 담당 API·DB·서버 연동·운영 문제 해결을 먼저 설명한다.
2. 깨비뚝딱의 LLM 출력 스키마·권한·수치 계산·revision 검증을 더한다.
3. 이번 후속 개발의 근거 추적·작업 상태 정합성·실제 측정을 증거로 제시한다.

실제 금융기관 계좌·거래 API를 연동했거나 은행 서비스 수준의 보안·성능을 검증했다는 뜻은 아니다.

## 약 2분 시연 순서

1. 로컬 스택을 켜고 예금 유지·해지 비교 화면을 요청한다.
2. 입력 폼과 비교 위젯, 원문 링크·자료 확인일을 펼쳐 보여준다.
3. 가상 조건을 입력하고 590,000원 계산 예시를 확인한다. 계산 후 근거·입력 상태가 보존되고 모델 호출은 추가되지 않는다는 trace를 설명한다.
4. 자료가 없는 기관·시점의 진단 결과를 보여주고 빈 근거를 성공으로 포장하지 않는다고 설명한다.
5. 비교표에서 추가 재검색의 회수 이득이 없었다는 결과와 once 기본값 선택을 설명한다.

## 직접 설명할 수 있어야 하는 질문

- 모델이 정하는 값과 서버가 정하는 값은 각각 무엇인가?
- 출처 ID 검증과 답변의 의미 검증은 왜 다른가?
- 작업이 재시작 중 끊기면 왜 자동 재실행하지 않는가?
- 단일 worker에서 동시 요청이 늘 때 무엇이 병목인가?
- 평가 문항의 유사 표현과 작은 corpus가 결과를 어떻게 제한하는가?
- 보안카드·OTP 해제를 일반 결제카드 해제에 사용하면 왜 안 되는가?

구현에는 Codex를 활용했다. 본인이 읽고 실행하며 이해한 범위를 기준으로 기여 내용을 다듬는다.
