# 지식 큐레이션 운영과 면접 설명

## 서비스와의 연결

깨비뚝딱의 원래 제품 흐름은 사용자가 채팅으로 상황을 설명하면 금융 기능을 위젯 화면으로 구성하는 것이다. 이번 도구는 그 제품을 개발·검수하는 사람이 참고할 금융 안내와 기술 문헌을 관리하는 내부 지식 처리 경로다. 문헌 검색 결과를 고객의 거래 실행이나 대출 자격 판단으로 연결하지 않는다.

공식 arXiv 초록 30편과 기존 금융 안내 요약 26개를 버전별로 관리한다. 논문은 금융 문서 수치 추론, 금융 감성 분석, RAG, 에이전트, 모델 적응, 추론 서빙으로 범위를 넓혔다. 전체 논문 본문을 분석한 것으로 설명하지 않는다. 공개 저장소에는 제목·버전 URL·해시를 보관하고 초록 원문과 생성된 검토 카드는 로컬 `var/`에 둔다.

## 수집과 변경 감지

공식 API가 반환한 논문 ID와 예상 제목을 함께 검사한다. ID가 틀렸는데 제목을 확인하지 않는 수집 실수를 막는다. 중복 ID, 누락된 응답, 잘못된 제목, 과도하게 큰 응답은 저장 전에 거부한다. 문서의 내용·출처 메타데이터 해시를 버전 키로 사용하고 과거 버전도 보관한다.

```bash
.venv/bin/python scripts/collect_research_corpus.py
.venv/bin/python scripts/refresh_knowledge.py
```

`--refresh`를 붙였을 때만 공식 API를 다시 조회한다. 기본 확장 집합을 아직 수집하지 않았다면 명시적으로 수집하라는 오류를 반환한다. 요청 처리 도중 모델이나 문헌을 임의로 내려받지 않는다.

## 복구 가능한 AI 검토 작업

작업 키는 문서 ID·원문 버전 해시·모델 식별자·프롬프트 버전으로 만든다. 같은 입력의 작업을 다시 등록해도 기존 작업을 재사용한다. 구형 카드 중 모델·프롬프트·현재 원문 버전이 일치하고 출처 위치 검사를 통과한 후보는 새 추론 없이 이관한다. 이관된 카드도 검토 대기 상태다.

| 상태 | 의미 |
| --- | --- |
| queued | 실행 대기 또는 제한된 일시 오류 재시도 |
| running | 임대 토큰을 가진 작업자가 처리 중 |
| prepared | 원문 위치 검증을 통과한 검토 대기 카드 |
| failed | 검증 실패 또는 재시도 한도 소진 |
| stale | 처리하던 원문 버전이 교체됨 |

SQLite `BEGIN IMMEDIATE`로 작업 소유권 취득을 직렬화한다. 추론 자체는 DB 쓰기 트랜잭션 밖에서 실행한다. 작업을 저장할 때 임대 토큰·만료 시각·현재 원문 버전을 다시 검사한다. 임대가 만료된 작업자의 늦은 결과는 새 작업 결과를 덮어쓰지 못한다. 기본 시도 한도는 3회이며 일시 오류만 지연 후 재시도한다. 잘못된 모델 출력은 종료한다.

모델 실행의 exactly-once를 주장하지 않는다. 서버가 중단되면 추론을 다시 할 수 있다. 대신 현재 소유권을 잃은 결과가 저장되지 않도록 막는다. 원문을 교체했다가 되돌린 경우에도 기존 시도 횟수를 보존하면서 재개한다.

```bash
.venv/bin/python scripts/curate_knowledge.py status
.venv/bin/python scripts/curate_knowledge.py enqueue --kind abstract
.venv/bin/python scripts/curate_knowledge.py work --limit 10
.venv/bin/python scripts/curate_knowledge.py audit
```

작업 수와 실행 예산을 제한한다. 실행 시간 예산은 작업 사이에서 확인하며 이미 실행 중인 모델 호출을 강제로 중단하는 기능은 아니다. 변경된 작업이 없으면 `LazyMLXGenerator`를 실제 적재하지 않고 종료한다.

## 검토와 원자적 버전 전환

모델은 서버가 만든 원문 구절 ID를 선택하고 분류·태그를 제안한다. 인용문과 시작·끝 위치는 서버가 원문에서 복사한다. 인용 위치·문서 해시·출처 URL을 검사한 뒤 `pending_review`로 저장한다. 출처 위치 일치는 분류의 정확성이나 과학적 사실의 진실성을 뜻하지 않는다.

검토 명령은 작업 ID, 승인 또는 반려, 검토자, 사유, 예상 검토 리비전을 요구한다. 오래된 검토 화면에서 덮어쓰면 충돌로 거부한다. 승인된 카드의 목록을 릴리스로 만들 때 현재 원문 버전과 검토 리비전을 다시 확인하고 활성 포인터를 한 트랜잭션에서 전환한다. 중간 항목에서 실패하면 일부만 발행하지 않는다.

이 릴리스는 내부 검토 카드 집합이다. 소비자 금융 데이터 저장소를 자동 교체하는 기능이 아니다. 승인·발행 명령은 로컬 CLI에서 명시적으로 실행하며 HTTP에는 상태·감사·검색 경로만 제공한다. CLI 검토자 이름은 운영 기록이며 별도 인증 체계를 구현했다는 의미는 아니다.

```bash
# JOB_ID, RELEASE_ID와 리비전은 status/inspect 결과를 확인해 입력한다.
.venv/bin/python scripts/curate_knowledge.py inspect JOB_ID
.venv/bin/python scripts/curate_knowledge.py review JOB_ID approved \
  --reviewer '검토자' --reason '검토 근거' --revision 0
.venv/bin/python scripts/curate_knowledge.py publish JOB_ID \
  --operator '운영자' --revision 0
.venv/bin/python scripts/curate_knowledge.py activate RELEASE_ID \
  --operator '운영자' --revision 1
```

롤백도 출처 버전과 승인 리비전이 여전히 유효할 때만 가능하다. 승인 취소나 원문 변경이 있으면 예전 릴리스의 카드가 다시 검색되지 않는다. 검색 중 승인이 취소되어도 마지막 리비전 검사에서 결과를 비운다.

| API | 역할 |
| --- | --- |
| GET `/knowledge/curation/status` | 상태·검토 수·만료 임대·활성 릴리스 |
| GET `/knowledge/curation/audit` | 출처 버전·인용 위치·검토 이력 재검사 |
| POST `/knowledge/reviewed-search` | 명시적으로 승인된 구절 카드 검색 |

감사 기록은 로컬 상태 재현을 위한 것이다. 변조 불가능한 보안 로그라고 주장하지 않는다. 검색에는 승인한 구절만 반환하며 문서 전체를 사실로 인증한 것처럼 취급하지 않는다.

## 면접에서 설명할 내용

> 채팅으로 금융 화면을 구성하는 서비스에서, 모델을 붙이는 작업 외에 지식의 변경과 검토 과정을 백엔드 문제로 다뤘습니다. 문서·모델·프롬프트 버전으로 작업을 식별하고, 중복 실행과 서버 중단을 고려한 임대 토큰을 구현했습니다. AI는 원문 구절 후보만 만들고 검토와 릴리스는 별도 리비전으로 관리합니다. 저장 전과 검색 후에 출처·승인 버전을 검사해 오래된 결과가 노출되지 않도록 했습니다.

3번에는 문헌 수집·지식베이스·데이터 정제·에이전트 보조 도구로 연결할 수 있다. 금융권과 대기업 백엔드 면접에서는 멱등성, 낙관적 동시성 제어, 트랜잭션 경계, 장애 복구, 캐시 무효화, 추론과 실제 데이터의 책임 분리를 설명하면 된다.

검수에는 동시 소유권 취득, 중단 후 재개, 늦은 결과 거부, 원문 교체·복원, 승인 취소, 검색 중 리비전 변경, 릴리스 실패의 원자성을 포함한다. 실제 실행 수치와 모델 비교의 한계는 별도 실험 결과 문서와 JSON 보고서에서 확인한다.

설계 근거: [SQLite 트랜잭션](https://sqlite.org/lang_transaction.html), [SQLite 격리](https://www.sqlite.org/isolation.html). 프로세스 간 분산 메시지 브로커나 다중 서버 배포를 구현한 것은 아니다.
