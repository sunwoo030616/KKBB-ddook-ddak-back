# 585개 메뉴의 상황별 복수 추천

`POST /api/menus/recommend`에 `{"message":"일본 여행 가고 싶어"}`를 보내면 상황에서 필요한 업무를 최대 3개로 나누고 각 업무에 대해 실제 E5로 메뉴를 검색한 뒤 JEV가 실제 메뉴를 선택한다. 기존 `/api/menus/select`의 단일 메뉴 계약과 9종 위젯 화면 경로는 유지한다. 새 경로는 메뉴 추천이며 화면 렌더링이나 거래를 실행하지 않는다.

기존 상황 추천 브랜치의 54개 업무 정의와 판단 코드를 정제된 585개 메뉴 카탈로그에 연결했다. 흐름은 JEV 업무 판단 1회 → 업무별 E5 검색 → JEV 메뉴/제안 근거 판단 1회다. 일반 해외여행 상황의 제품 기본 제안은 환전·해외 QR 결제·여행보험이다. 특정 기능만 요청하거나 이미 준비·가입했거나 명시적으로 제외한 업무는 추가하지 않는다. 국가별 실제 QR 지원·상품 가입 가능 여부나 거래 완료를 보장하는 뜻은 아니다.

단일 업무는 E5 Top-40, 복수 업무는 업무별 Top-12를 실제 검색한다. 후보 밖 메뉴·잘못된 응답·confidence를 거부한다. 애매하거나 지원 밖인 요청은 조기 확인 요청/no_match로 끝나며, 일부 메뉴만 확정되면 partial로 응답한다. `recommendations`는 explicit/suggested/uncertain 근거를, `candidateIdsByNeed`는 실제 후보를 제공한다. 입력은 외부 전송 전 기존 민감정보 마스킹을 거치며 연속 JEV 장애에는 회로 차단을 적용한다. API 키는 기존 JEV_AI_API_KEY, 모델과 confidence 설정은 기존 변수를 사용한다.

## 검증

- 전체 로컬 테스트 134개, 실패 0·오류 0·건너뜀 6개. 128개 통과. 로그: backend-tests.log.
- 실제 E5/JEV 개발 확인: smoke-japan.json. 환전신청 kb_menu_0323, 해외 QR 결제 kb_menu_0413, 해외여행보험 kb_menu_0602를 모두 반환했다. JEV 호출 2회.
- 원문 단독 E5 검색에서 위 질문의 세 정답은 각각 95위·184위·62위여서 단순 Top-40만으로는 누락됐다. 새 경로는 상황 업무별 의미 검색으로 후보를 찾는다.
- 첫 개발 확인에서는 QR 업무의 planning confidence가 낮아 제외됐다. 사용자 요구인 기본 여행 묶음을 제품 정책에 명시한 뒤 다시 확인했다. 첫 응답은 smoke-japan-before-policy.json에 보존했다. 이 질문은 정책 개발에 사용했으므로 독립 평가가 아니다.

## 한계

최대 3개 업무, 미리 정의한 54개 업무와 그 밖의 명시적 요청 fallback을 사용한다. 임의의 모든 상황·복합 의도를 완벽히 분해한다고 보장하지 않는다. 같은 fallback으로 묶이는 여러 미지원 업무는 누락될 수 있다. confidence는 보정된 정답 확률이 아니며 낮은 확신의 추가 제안은 생략될 수 있다. 독립 라벨 검수·자연 사용자 표본으로의 성능 확인이 필요하다. 기존 단일 선택 300문항 정확도는 이 새 경로의 성능이 아니다.
