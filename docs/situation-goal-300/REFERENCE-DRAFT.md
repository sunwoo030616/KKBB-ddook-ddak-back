# 상황형 복합 요청 평가 기준표 — 검토 초안

**미승인 초안이며 아직 300문항이나 API 평가를 실행하지 않았다.** 이전 95%는 이 평가의 정확도가 아니다. 이 표의 정답은 평가기에만 들어가며 모델 프롬프트·분기 규칙·메뉴 검색어 목록으로 넣지 않는다.

## 검토할 기본 원칙

1. 입력에 메뉴나 처리할 업무 목록을 나열하지 않는다. 생활 목표·사건·제약으로부터 필요한 준비를 추론하게 한다.
2. 포괄 목표형과 구체 상황·제약형을 별도로 집계한다. 메뉴명을 나열한 질문은 새 300문항에 섞지 않는다.
3. 필수는 거래를 실행하라는 뜻이 아니라 추천에 포함해야 한다는 뜻이다. 제안과 실행·가입 완료를 구분한다.
4. 모든 목표가 복합 업무를 의미하지 않는다. 추가 확인이나 단일 안내가 타당한 사례는 별도 경계 평가로 두며 복합 300개의 점수를 높이는 데 사용하지 않는다.
5. 메뉴 하나가 조회와 신청을 모두 처리하면 메뉴 두 개를 억지로 필수로 만들지 않는다. 상위 메뉴·세부 메뉴의 기능 중복을 검수한다.
6. 대체 정답은 실행 전에 한정해서 확정한다. 단순히 관련된 메뉴를 전부 정답으로 인정하지 않는다. 기본안은 허용 정답 집합 중 하나와 완전히 일치해야 성공이며, 필수 누락·금지/무관 메뉴 추가·불필요한 중복은 실패다.
7. 선택 추천은 허용하는 개수와 조합까지 사전 확정한다. 초안은 최대 2개 추가를 제안하지만 사용자 검토가 필요하다.
8. 이미 완료·제외한 업무는 다시 필수로 요구하지 않는다. 자격·보유 상품·교통수단·가입 상태를 임의로 가정하지 않는다.
9. 금융상품 추천은 안내만 평가한다. 특정 대출·보험·투자 가입을 모든 상황의 필수 정답으로 만들지 않는다. 여행보험은 사용자가 제시한 여행 예시에 따른 검토 항목이다.

## 대표 10개 상황과 2개 경계 사례

아래의 필수 항목도 합의 전 제안이다. 여행 예시 외의 기본 묶음은 사용자 요구로 확정된 것이 아니다.

| 번호 | 상황만 제시한 입력 예시 | 필수 추천 초안 | 선택 추천 초안 |

| S01 | 일본 여행 가고 싶어. | 환전신청 / 해외 QR 결제 / KB손해보험 다이렉트 해외여행보험 | 스타뱅킹 해외결제 / 트래블러스 체크카드 / 리브모바일 로밍서비스 |
| S02 | 차 없이 부모님과 부산에서 1박 하고 오려고 해. | 기차표(KTX·SRT) 예매 / KB Pay 여행 | 없음 |

| S05 | 타던 차를 이제 팔려고 해. | 차량 시세조회 / 팔아줘 차차차 | 없음 |

## 행별 검토 포인트

- **S01**: 환전·QR·보험은 사용자 예시. 일반 해외결제·여행카드를 QR의 대체 정답으로 인정할지는 검토 필요. 금지: 불필요한 대출·투자, 거래·가입 완료 주장.
- **S02**: 교통·숙박을 독립 준비로 제안한다는 제품 기준 초안. 특정 휴양림·캠핑장으로 임의 축소하지 않음. 금지: 근거 없는 캠핑·휴양림 한정, 여행자보험 필수화.
- **S03**: 계좌 준비·정책 지원을 기본 추천으로 볼지는 사용자 검토 필요. 대출 자격·지원금 수급 가능성을 보장하지 않음. 금지: 대출 자동 추천, 신용한도 확정, 임의 적금 가입.
- **S04**: 시세·세금 검토를 필수 제안으로 볼지는 검토 필요. 특정 대출이나 청년 자격을 가정하지 않음. 금지: 자격 미확인 전용 상품 강제, 임의 대출 신청.
- **S05**: 가격 확인과 판매를 별도 준비로 제안한다는 초안. 내 차 관리 시작하기(595)를 가격 조회의 동등 대체로 볼지 검토. 금지: 자동차 구매 대출·보험 가입을 필수 정답으로 추가.
- **S06**: 정보 파악·상담을 기본 제안으로 둘지 검토 필요. 특정 상품 가입을 목표로 간주하지 않음. 금지: IRP·보험·투자상품 무조건 가입, 수익 보장.
- **S07**: 손실 대응과 당장 필요한 현금을 별도 업무로 해석. 출금 도움말(211)만으로 해결로 볼지는 검토 필요. 금지: 현금서비스·리볼빙을 출금의 대체로 추천.
- **S08**: 만료된 여권과 해외 통신을 별개 준비로 해석. 통신 추천을 필수로 둘지는 검토 필요. 금지: 완료한 환전·보험 재추천, 여권 유효성 확인만 하고 끝냄.
- **S09**: 현금흐름 파악과 지원 탐색의 두 목적. 정책자금과 세금·고용혜택을 동등 대체로 볼지는 검토 필요. 금지: 매출채권 대출 등 미요청 대출 강제.
- **S10**: 연결이 이미 되어 있는지 모르면 확인을 허용할지, 안내 두 메뉴를 제안할지 검토 필요. 잔액 모으기는 실제 자금 이동이므로 자동 요구하지 않음. 금지: 불필요한 자금 이체·잔액 모으기 강제.
- **C01**: 대상 업무 자체를 알 수 없으므로 needs_clarification. 복합 요청 정확도 300개의 분모에 섞지 않음. 금지: 임의 메뉴 여러 개 반환.
- **C02**: 투자 대상·목적·성향을 확인할지, 일반 안내 하나를 제안할지 제품 정책 검토. 복수 상품 가입을 정답으로 강제하지 않음. 금지: 특정 상품·투자금·수익률 단정.

## 기준 확정 뒤의 300문항 구성안

- 우선 이 대표 기준을 검토한 뒤 여행 이외 영역을 포함해 상황군을 확장한다. 검토되지 않은 묶음을 임의로 300개 만들지 않는다.
- 예: 포괄 목표 150개 + 상황·제약 150개. 문장만 바꾼 반복은 같은 상황군으로 표시하고, 실제 상황군 수·메뉴 수·중복을 함께 공개한다. 300개를 300개 독립 상황이라고 부르지 않는다.
- 가족/완료/제외/기보유 상태를 바꾸면 정답도 바뀌도록 검수한다. 단순 말투 변형만으로 표본을 늘리지 않는다.
- 같은 고정 300문항·같은 GPT-4.1에서 단독 LLM과 삼단계 구조를 비교한다. 개발용과 최종 검증용 상황군을 분리한다.
- 정확도는 사전 확정한 허용 정답 집합 완전일치율로 이름을 명시하고, 필수 업무 Recall·추가 메뉴율·확인 요청·오류도 함께 보고한다. 이전 단일 정답 집합 지표와 이름 없이 섞지 않는다.
- 원문·정답·허용 대체·금지·단가·실행 설정을 고정한 뒤 실행한다. 정답표를 두 모델에 전달하지 않는다. 결과를 본 뒤 라벨을 바꾸어 90%를 만들지 않는다.

사용자 검토 요청: 행 번호별로 필수에서 뺄 것, 추가할 것, 동등 대체로 인정할 메뉴, 선택 추천의 허용 개수를 알려주면 된다.
