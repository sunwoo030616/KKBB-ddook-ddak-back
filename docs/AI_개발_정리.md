# 깨비뚝딱 AI·백엔드 개발 정리

2026-11-03. 제품의 중심은 **채팅에 상황을 입력하면 필요한 금융 업무 화면을 구성하고, 후속 요청으로 그 화면을 바꾸는 경험**이다. 원본 수상 자료의 채팅 → 의도·상황 → 기능 조합 → 화면 흐름을 유지한다.

## 구현된 AI 흐름

1. **상황 병합:** 목적지·기간·금액·통화 등 typed slot을 세션에 합친다. 사용자가 직접 말한 값과 목적지에서 조회한 값을 구분한다. 모델의 슬롯 제안은 이번 발화의 인용과 맞는지 검사한다.
2. **업무 위젯 검색:** BGE 다국어 cross-encoder가 상황과 위젯 목적 사이의 관련도를 추론한다. 단일 문장 검색과 절별 후보 합집합 경로를 비교한다. Apple GPU에서는 float16으로 실행하고 CPU에서는 float32를 사용한다. 장치 변경 전후 점수 차이도 측정했다. 활성 registry와 프론트가 렌더링할 수 있는 type만 다룬다.
3. **구조화 화면 설계:** 로컬 Qwen3-4B 4bit가 후보 안에서 위젯·우선순위·제목·확인 요청을 생성한다. Outlines의 토큰 제약과 Pydantic 재검증을 적용한다.
4. **서버 컴파일:** 허용 목록·중복·의존관계·상충 액션·최대 화면 크기를 검사한다. 필요한 입력 폼을 붙이고 위상 정렬과 data binding을 만든다.
5. **실제 데이터 연결:** 예금 유지/해지·대출 상환은 서버 Decimal 계산을 사용한다. 공식 근거와 참고 환율은 출처가 있는 데이터 공급자를 통해 연결한다.
6. **다중 턴 화면 갱신:** widget ID 기준 patch와 SQLite revision을 사용한다. 유지된 계산·입력 상태를 보존한다. 순수 기간·금액·폼 변경은 모델 호출 없이 갱신한다.
7. **비동기 실행:** Spring 작업 API, 단일 inference worker, 중복 요청 ID, 진행 조회와 프론트 상태 보존을 연결했다. 폴링 연결 오류는 동일 작업을 재조회하며 모델을 중복 제출하지 않는다.

모델·토크나이저를 포함한 로컬 공개 가중치만 사용한다. 유료 OpenAI API 키가 없어도 동작한다. 설치한 라이브러리를 사용한 시스템 개발이며 새 모델 아키텍처를 발명했다는 주장은 아니다.

## 추가 실험과 채택 판단

### LLM 의미 검토

요청한 기능의 누락·금지·유지를 원문 인용과 실제 화면 이력으로 검토하고 한 번만 수정하는 경로를 구현했다. 검토 출력에도 요청별 동적 JSON 스키마를 적용했다.

그러나 실제 12문항 비교에서는 연결 오류 1건을 제외하면 두 방식 모두 6/11이었다. 지연 중앙값은 약 39초 → 81초로 늘었다. **정확도가 개선되었다고 주장하지 않고 기본값을 off로 뒀다.** 검토·수정은 명시적 실험 옵션으로 남겼다.

- [구현·프로토콜](LLM_의미검토_실험.md)
- [실제 비교 결과](../reports/semantic-review-results.md)

### 복합 요청 검색과 미지원 요청 중단

단일 문장의 큰 의도가 작은 의도를 후보에서 밀어내는 문제를 확인했다. 원문과 최대 3개 보조 절을 실제 cross-encoder로 검색하고 후보를 합치는 경로를 추가했다. 모든 관련도가 매우 낮은 요청은 억지로 위젯을 고르지 않고 안내로 반환한다.

- [설계·제약·재현](복합요청_위젯검색.md)
- 실제 모델 비교: `reports/component-query-v1.json`의 마지막 `summary` 확인.

이 자료는 실패를 보고 반복 개선한 개발 진단이다. 외부·독립 벤치마크로 표현하지 않는다. 모의 모델 단위 테스트와 실제 가중치를 실행한 평가를 구분한다.

### 보조 임베딩 학습

52개 관련성 학습 질문으로 임베딩 모델 마지막 2개 층의 3,548,928개 파라미터를 실제 로컬 학습한 기록도 있다. 일부 단일 근거 검색은 좋아졌지만 복합 질문의 Recall@2가 나빠져 기본 검색기로 채택하지 않았다. 이를 현재 화면 모델을 fine-tuning했다고 표현하지 않는다.

- [보조 모델 실험](../RESEARCH_README.md)

## 면접·포트폴리오에서 설명할 중심

> 금융 상황을 채팅으로 입력하면 업무 위젯을 구성하는 Generative UI 백엔드를 확장했습니다. 로컬 소형 LLM의 구조화 출력과 신경망 후보 검색을 연결하고, 후보 누락·미지원 기능 선택·다중 턴 상태 손실을 구분해 측정했습니다. 화면 계약과 의존관계는 서버에서 검증하고, 금융 수치는 모델이 생성하지 않고 출처 데이터와 계산기로 공급했습니다. 추가 LLM 검토는 실제 비교에서 이득이 확인되지 않아 기본 경로에서 제외했습니다.

정확도 수치를 넣을 때는 데이터 규모, 개발 평가라는 사실, 연결 오류 처리, 실패와 지연을 함께 적는다. 현재 로컬 데모를 운영 환경의 은행 서비스나 실거래 완료 서비스로 표현하지 않는다.

## 코드와 실행

- `rag_backend/canvas.py`: 화면 DSL·후보 검색·계획·컴파일·상태 갱신.
- `rag_backend/component_queries.py`: 복합 요청의 검색 관점과 관련도 집계.
- `rag_backend/semantic_review.py`: 인용·이력·capability로 제한한 의미 검토.
- `rag_backend/canvas_context.py`: 상황 정보 병합과 출처 검증.
- `rag_backend/canvas_jobs.py`: 모델 작업 큐와 중복 제출 방지.
- `../kkbb-ddook-ddak-front/src/pages/ChatPage.jsx`: 원래 채팅 경험과 실제 위젯 렌더링 연결.
- [전체 실행 방법](../FRONTEND_INTEGRATION.md): `.venv/bin/python scripts/dev_stack.py`, 접속 http://localhost:5173.

아직 실제 금융기관 거래·계좌·인증 API는 연결하지 않았다. 미연결 금융 액션은 실행되지 않는다. 등록한 16개 type을 조합하는 시스템이며, 임의의 새 프론트 코드를 실시간 생성하는 시스템은 아니다.

현재 React는 multi 검색과 review off를 명시한다. 직접 API 요청의 기본 retrieval_mode는 single이므로 multi 경로를 쓰려면 요청에서 지정한다.


## 완료된 시스템 비교

[전체 결과](../reports/component-query-results.md): 연결 오류가 있는 s11 쌍을 제외한 11문항에서 정확 위젯 집합이 6/11 → 10/11로 늘었고, 비교 가능한 문항의 후보 Recall은 0.833 → 1.000이었다. 전체 12개 요청은 6/12 → 11/12였지만 기존의 연결 오류를 모델 오답으로 해석하지 않는다. 새 시스템의 응답 중앙값은 18.11초였다. CPU와 MPS의 실행 환경·정밀도도 함께 바뀌었으므로 엄밀한 속도 향상률이나 검색 분할만의 인과 효과로 주장하지 않는다.

이전 단계에서는 국내 부산 여행에서 해외 금융 기능이 모두 필요 없다는 s08이 불필요한 예금보호 위젯을 선택했다. 이후 검색 전 의도 계약 단계에서 이 사례를 보완했다. 낮은 관련도의 강제 선택 문제를 일부 줄였지만 부정 범위·요청 부재를 완전히 해결하지 못했다. 이 실패도 결과에 포함했다. 같은 개발 자료로 확인한 수치를 전체 서비스 정확도나 독립 연구 성능으로 표현하지 않는다.

최종 React→Spring→로컬 신경망 브라우저 검증에서 비용 비교·상환표·각 입력 폼 4개를 함께 확인하고 예금보호 위젯의 제외도 확인했다. [상단 화면](../reports/react-ai-composition.png), [비교·대출 화면](../reports/react-ai-composition-loan.png), [검증 메타데이터](../reports/ai-enhancement-verification.json)에 증거를 남겼다. Python 133개, 프론트 5개 테스트와 프론트 lint/build를 통과했다.


## 최신 보강: 검색 전 의도 계약과 실행 제약

원문 구간의 request/exclude/context/mixed 분류 → 신경망 검색 → 제외 위젯의 생성 스키마 차단을 추가했다. 처음에는 설명만 제외하고 실제 위젯을 남기는 회귀가 생겨, 제외 type을 요청별 registry와 decoder 후보에서 함께 제거했다. 중복 type 출력은 동일 widget ID로 정규화하며 서로 다른 기능은 합치지 않는다.

[최종 개발 집계](../reports/intent-contract-results.md)에서 기존 회귀 12개와 새 표현 8개가 맞게 구성됐다. 이전 실패를 보고 수정·재시험한 내부 자료이며 외부 정확도 주장이 아니다. 19개 정상 자동 구성 기록은 유지하고 실패한 s10을 실제 모델로 재시험했다. 최초 실패(v1), 제외 제약 적용 후 중복 실패(v2), 재시험(v3), 정확한 화면 비우기 라우터 재시험(final)을 모두 남겼다. 새로 20개 전체를 한 번에 추론한 실행은 아니다.

새 8개 표현은 기존 방식도 8/8이어서 이 자료만으로 일반 성능 향상을 주장하지 않는다. 추가 의도 분류는 지연을 늘리므로 제외·완료·유지·교체 표현이 있는 요청에만 사용한다. 단순 기간·금액·계산과 정확한 전체 화면 비우기는 추가 LLM 호출 없이 처리한다.

현재 React는 `intent_mode=auto`, `retrieval_mode=multi`, `review_mode=off`를 명시한다. API의 intent 기본값은 off다. 삭제한 위젯의 금융 입력 초안은 제거하고 남은 위젯의 입력값은 보존한다. 최종 Python 148개와 프론트 7개 테스트, 프론트 lint/build를 통과했다. [구현과 재현](LLM_의도계약.md).

실제 프론트 통합 증거: [부정 요청](../reports/react-intent-negative.png), [후속 편집](../reports/react-intent-edit.png), [추가된 상환 위젯](../reports/react-intent-edit-loan.png). 검증 메타데이터는 `reports/intent-contract-verification.json`이다. 계산과 정확한 화면 비우기 실제 검사도 2/2 통과했다.
