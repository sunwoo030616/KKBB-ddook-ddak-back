# E5→JEV만 개선한 실제 재측정

**OpenAI 호출0회. 평가용 정답·허용 대체는 바꾸지 않았다.** 기존 문항은 개발 회귀, 새100개는 같은10개상황의 새로운 표현이다. 부분 적중은 허용 메뉴 하나 이상을 포함하는 경우이며 완전 업무 해결률이 아니다.

## 기존100개 개발 회귀

부분 적중 84% → 93%, 허용 메뉴 비율 54.95% → 59.67%.

같은 이전100문항의 단독 GPT-4.1 부분 적중은89%였다. 개선판93%가 이 점수를 넘었으나, 그100개는 개발에 노출됐으므로 독립적인 LLM우월성 검증이 아니다. 새100개에서 단독 LLM은 호출하지 않았다.

오프라인 분해 확인: 개선판의 실제 동일 검색 후보·동일 Noul판단을 그대로 두고 개별 확률 상위3개만 뽑으면 88%, 최종 조합 선택은 93%다. 단순히 추천 수를3개로 채운 효과만으로 전체 상승을 설명하지는 못한다. 이 분해는 새API측정이 아닌 개발 분석이다.

## 변경 내용

1. 원문 E5 Top80은 보존하고 일반 동의어·키워드 검색의 보완 후보를 최대20개 추가했다. 실제 메뉴만 최대100개이며 가상 벡터·유사도·정답ID검색표를 쓰지 않는다.
2. JEV의 실제 메뉴별 판단과 E5 벡터의 MMR로 후보10개를 추렸다. 메뉴 텍스트에서 연결·조회·상담·계산·실행 같은 일반 기능 역할을 표시한다.
3. 후보가 충분하면 실제3개메뉴 조합120개 중 JEV가 하나를 선택한다. 목적별 고정 메뉴 묶음을 넣지 않았고 단계별 판단의 서로 다른 답을 가정하지 않는다. none/unsure도 가능하다.

## 한계·비용·검증

- 처음 조합 실험은20개중15개로 실패했고 보존했다. 두 번째 개발20개는19개였다. 최종 소스·질문·정답·임계값은 최종 API실행 전에 고정했고 결과를 본 뒤 바꾸지 않았다.
- 새100개는 10개 승인된 상황의 새표현이지 새로운100개 독립상황이 아니다. 개발과 같은 상황군·메뉴를 공유하므로 독립 일반화나 실제사용자90%보장은 아니다.
- 개선판은 후보가 충분하면3개를 반환한다. 기존은0.7기준으로3개이하만 반환한다. 추천수 차이·추가 오답·완전일치도 표에 함께 보존한다. 부분적중93%를 필요한 일을 모두 처리한 정확도93%라고 표현하면 안 된다.
- 원래 정답표의 은퇴자산·연결 기능 등 동등성 누락 가능성도 그대로다. 이 실험에서는 라벨을 수정해 점수를 올리지 않았다. 추가 사람검수가 필요하다.
- 동의어·기능역할은 일반 텍스트 규칙 기반이므로 범위 밖 표현·메뉴에서 오분류할 수 있다. 별도 상황군·실사용 검증 전에는 제품에 곧바로 배포하지 않는다.
- JEV가 조합 하나를 고른 confidence는 업무 성공확률이 아니다. 원래0.6기준을122개선택문제에 무작정 적용하지 않았고, 선택값·확률은 원시로그에 보존했다.
- 시간은 로컬 E5/키워드 처리·실제JEV 1~2회·선택을 포함하고 기동/인덱스준비는 제외했다. 1회 실행의 네트워크·모델 변동을 포함한다.
- 비용은 관측JEV입력×$0.042/M, 출력무료인 [공식단가](https://help.typesafe.ai/articles/5187202169-how-much-does-jev-cost)에 따른 API추정이다. 로컬E5 CPU/운영비·세금·개발비·제외한 한도오류 시도는 제외하고 청구서가 아니다.
- 순수JEV키만 필요하며 OpenAI키/호출 의존성은 없다. 기존 프로젝트 화면/기본API를 바꾸거나 GitHub에 게시하지 않았다.
