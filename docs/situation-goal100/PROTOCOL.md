# User-approved situation-only 100-case comparison

The user approved the situation reference draft and acceptable alternatives (“다 인정”), then reduced the requested evaluation from 300 to 100. This run replaces the prior mixed/explicit-request experiment as the intended task. Presentation page construction remains canceled. Results stay local; no GitHub publication is approved.

Data: 100 new strings, 10 reviewed situation families ×10 expressions. Five families are broad goals (50), five include circumstances/constraints (50). Inputs do not enumerate a list of menus to execute. This is 100 expressions, not 100 independent intents. It is a synthetic, user-approved product reference, not independent expert or traffic validation. S10 includes the not-yet-connected account state to resolve the ambiguity identified during review. Additional clarification boundary cases are excluded from the 100 rather than used to inflate accuracy.

Before either provider is called, cases, canonical IDs, finite acceptable alternative sets and required outcome groups are frozen. Primary metric is exact equality to one approved menu-ID set AND expected status. It is named acceptable-set exact match, not the old canonical single-set accuracy. Canonical exact match is retained separately. Required-outcome recall, allowed-menu precision, disallowed additions and errors are separate metrics. No post-result label edits are allowed.

Alternatives are evaluated only by the scorer and are not passed to model prompts or routing code. The frozen general hybrid inference is unchanged (source 18d7f96). The same pinned GPT-4.1-2025-04-14 and compact direct baseline from the prior comparison are used; JEV is pinned at 1.14.0. Up to 8 outputs in both conditions. Baseline receives IDs/names/purposes, hybrid planning names/purposes plus JEV gets retrieved candidates' selection conditions; this is an end-to-end configured-pipeline comparison, not identical detail fields.

S01 accepts QR, the general overseas-payment entry or travel card as payment alternatives. A travel card may accompany one QR/general-payment channel; QR plus its general parent is not counted as two independently needed services. Roaming is an optional addition. Other approved choices include property-pricing entry alternatives, vehicle-pricing entry alternatives, cashless-withdrawal help, and policy/tax/employment-support alternatives. These are finite sets in accepted-reference.json, not an unrestricted “related menu” rule.

Run scope authorized by the latest request: 100 cases per condition =200 OpenAI calls, up to200 JEV calls. Requests and actual menu data go to the same providers already authorized; labels do not. Quota-only retries (up to4 attempts) replace quota rows as the user requested; original attempts and any unknown usage are retained separately and excluded from final comparison tokens/cost. Other model/format/accuracy errors are never retried. Shared conservative rolling-minute pacing avoids duplicate scheduling and excludes queue delay from HTTP latency.

Cost: published standard rates and raw usage; OpenAI uncached input $2/M, cached input $0.50/M, output $8/M; JEV input $0.042/M, output free, checked 2026-11-15. Cached input is part of input. Local E5 CPU/hosting, tax, account discounts, development calls and excluded quota attempts are not included; it is an estimate, not an invoice. Sources: https://developers.openai.com/api/docs/models/gpt-4.1 and https://help.typesafe.ai/articles/5187202169-how-much-does-jev-cost .
