# PDF 기준으로 고정한 서비스 흐름

기준 자료: KB AI Challenge 대상 발표자료, 52쪽. 2026-11-03에 관련 화면 18·19·21·29·34쪽을 직접 렌더링해서 다시 확인했습니다.

**시작점은 기존 채팅 화면입니다. 사용자가 상황을 채팅으로 입력하면, AI가 필요한 금융 기능을 판단해 실행 가능한 위젯 화면으로 구성합니다.** 검색 답변이나 별도 계산 도구 페이지를 제품의 중심으로 삼지 않습니다.

| PDF | 서비스 의도 | 현재 구현과 남은 부분 |
| --- | --- | --- |
| 18~19쪽 | 상황을 대화로 입력하고 금융 기능 화면을 제공 | 미리보기를 채팅 시작 → 생성 캔버스 흐름으로 수정. 기존 React의 로컬 채팅·위젯 흐름과 v2 연결 완료. 공개 배포 미변경 |
| 21쪽 | 상황·맥락 분석, 기능 판단, 우선순위, UI 구성 | 실제 cross-encoder로 위젯 후보 검색 후 로컬 LLM이 type·priority·제목 제안 |
| 22~24쪽 | 검증된 컴포넌트를 선언적 스키마로 조합 | 승인된 16개 type, JSON 제약, 서버 재검증, 입력→결과 의존관계 연결 |

| 34쪽 | “일본 여행” 다음 “3박4일”의 파라미터를 합쳐 재구성 | 위젯 구성·계산 상태·revision은 보존. 여행지·통화·기간·금액의 typed slot과 출처 검증·병합 구현. 범용 언어 이해를 보장하지 않음 |

**현재 통합 결과:** [기존 React + 맥락 + 작업 자동화](../FRONTEND_INTEGRATION.md). 아래는 초기 계획 기록이며 완료 항목은 위 표를 기준으로 확인합니다.

## 앞으로의 우선순위

1. 기존 프론트의 채팅 → 캔버스 전환에 v2 계약을 연결하고 기존 UI 유지.
2. PDF 34쪽 예시처럼 후속 대화의 목적지·통화·기간·금액을 typed slot으로 병합하고 출처를 기록.
3. DB registry·후보 검색·hot on/off를 기존 렌더러 capability와 함께 검증.
4. 위젯 선택 평가를 넘어 대화 후 화면의 기능 누락·불필요한 기능·상태 보존·작업 완료 가능성을 평가.
5. 간단한 요청과 복합 요청의 모델 경로를 분리하고 정확도·지연·호출량 비교.

RAG, 재정렬, 임베딩 학습은 이 흐름에서 필요한 위젯을 찾거나 위젯의 안내 데이터를 공급할 때만 제품에 연결합니다. 보조 실험 수를 늘리는 것으로 서비스 고도화를 대신하지 않습니다.

## 현재 검증의 한계

`canvas-local-v3.json`의 개발용 8개 사례에서 위젯 집합 정확 일치는 6개입니다. 카드 정지 해제와 국내여행 부정 요청에서 실패가 남았습니다. 독립 벤치마크나 배포 품질 수치로 소개하면 안 됩니다. 기존 화면과의 실제 사용자 흐름 검증이 다음 핵심입니다.
