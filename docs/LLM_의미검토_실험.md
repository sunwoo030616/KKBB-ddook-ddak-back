# 채팅으로 구성한 금융 화면의 의미 검토 실험

2026-11-03. 기존 깨비뚝딱의 **상황 채팅 → 금융 기능 조합 → 위젯 화면**을 확장한다. 일반 금융 챗봇으로 바꾸지 않는다.

## 해결하려는 오류

JSON 구조와 위젯 ID가 맞아도 요청을 제대로 수행한 화면은 아닐 수 있다. “보험 빼줘”를 무시하거나, 예금 비교에 대출 상환표를 추가하면서 기존 비교를 없애거나, 후보 검색에서 필요한 위젯이 탈락하는 오류를 따로 다룬다.

## 구현

1. BGE cross-encoder가 활성 위젯 후보를 검색한다.
2. 로컬 Qwen3-4B 4bit가 제한된 JSON 스키마로 초안을 생성한다.
3. 같은 모델이 전체 활성 업무 카탈로그를 보면서 필수·금지·유지·불필요 위젯을 검토한다. 검토에는 이번 요청의 정확한 인용이 필요하다.
4. 서버가 인용 일치, 현재 화면 이력, frontend capability, 상충 조건을 검사한다. 잘못된 검토는 버린다.
5. 유효한 검토에 누락·불필요 기능이 있으면 후보를 확장하고 **한 번만** 화면을 다시 생성한다.
6. 수정본이 필수/금지 조건과 화면 컴파일 검사를 통과하면 채택한다. 실패하면 구조적으로 유효했던 초안을 유지한다.
7. 계산·공식 근거·환율은 기존 서버 공급자를 사용한다. 검토 모델은 금융 수치나 실제 거래 완료를 생성하지 않는다.

원문 인용은 모델이 문장을 지어냈는지 확인하는 장치다. 인용한 문장에 대한 의미 해석까지 참으로 보장하지 않는다. 같은 모델의 자기 검토 역시 오답을 만들 수 있다.

기본값은 `off`다. `review_mode`는 `off`(초안만), `audit`(검토 기록만), `repair`(검토와 제한적 수정), `auto`(후속·복합·제외 표현의 선택적 검토)를 받는다. 순수 기간·금액·계산 폼 갱신은 이 옵션과 무관하게 모델 호출을 건너뛴다. 진행 상태 `reviewing`, `refining`은 실제 작업 단계이며 React 채팅에 표시한다.

## 근거와 한계

[Self-Refine](https://arxiv.org/abs/2303.17651)은 같은 모델의 피드백과 재생성을 활용한다. 반면 [Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798)는 외부 피드백 없는 자기 수정이 추론 성능을 악화시키기도 한다고 보고한다. 두 논문의 실험 결과를 이 작은 금융 UI 시스템의 성능으로 옮겨 주장하지 않는다. 여기서는 서버 제약을 붙인 별도 제품 실험을 한다.

## 재현과 평가

```bash
.venv/bin/python -m pytest tests_rag/test_semantic_review.py -q
.venv/bin/python -m rag_backend.evaluate_semantic_review
```

- 데이터: `data/semantic_review_cases.json`, 검토 모델 실행 전 작성한 12문항.
- 비교: 같은 질문·동일 모델·동일 카탈로그에서 `off`와 `repair`를 쌍으로 실행.
- 후속 요청은 동일한 위젯 구성을 세션 DB에 넣은 실험 fixture다. 이전 턴을 모델이 실제 생성한 것으로 가장하지 않는다.
- 정답 위젯 목록은 평가기에만 전달하고 모델 프롬프트에 넣지 않는다.
- 정확 위젯 집합 일치, 개선/악화 사례, 실제 지연, 거부된 검토를 전부 남긴다.
- 개발자가 작성한 작은 진단 자료다. 실패를 본 뒤 수정한 버전은 추가 개발 평가이며 외부 블라인드 벤치마크가 아니다.
- CPU reranker와 Apple Silicon 모델을 같은 개발 장비에서 순차 실행한다. 실행 순서·캐시·열 상태에 따른 지연 차이가 있어 엄밀한 성능 측정이 아니다.

결과 파일: `reports/semantic-review-v2.json`. 실행 중에는 중간 결과이며 마지막 `summary`가 있어야 완료된 비교다.

검토 출력의 preserve/unnecessary 후보도 이번 요청의 실제 이전/초안 위젯 ID로 제한하는 동적 JSON 스키마를 적용했다. 초기 v1의 이력 오류는 `reports/semantic-review-v1-contract-failure.json`, 실행 환경 중단 기록은 `reports/semantic-review-v2-interrupted.json`에 보존했다. 비교가 완료되면 `python3 scripts/summarize_semantic_review.py`로 집계 표를 재생성한다.

완료 결과는 [비교 결과](../reports/semantic-review-results.md)에 있다. 연결 오류 1건을 제외하면 두 방식 모두 6/11이며 자기 검토의 정확도 향상 근거는 없었다. 지연 때문에 기본 경로에서 제외했다. 검토 실험 자체와 제약 코드는 선택 가능한 경로로 유지한다.
