# 개발 현황과 다음 작업

## 완료한 기능

- **제품 흐름:** 채팅으로 금융 위젯 화면을 구성하고 서버가 계산·근거·입력·리비전을 검증한다. 문헌 검색은 내부 개발·검토 도구다.
- **본문·복수 인용:** RAG·Speculative Decoding 공식 PDF의 첫 3페이지를 연결했다. 문서 hash와 PDF hash, 추출기 버전, 페이지·정확한 텍스트 위치를 보존하고 요청 절당 두 인용까지 반환한다.
- **검색·검증:** 다국어 원문 검색, 영어 재순위, 명시 조건, 저자 주장 구간, 본문 후보 압축과 선택적 LLM 검증을 연결했다. ID·인용·URL·버전은 서버가 작성하고 재검사한다.
- **프롬프트:** 실패한 v4 중첩 후보를 보존하고, 검증된 문구·평면 인용 슬롯을 사용하는 v5로 복구했다. 모델의 슬롯 선택과 서버의 문헌 선택을 분리한다.
- **분리 평가:** 기존 핵심 24/24·추가 검사 12/12. 구현 전 커밋한 별도 문항은 최초 10/12. 외부 주석 SciFact 표본은 문헌 9/10·정답 근거 문장 하나 이상 포함 6/10이었다. 서로 다른 평가의 의미를 구분한다.
- **실패 후 처리:** 사전 고정 문항의 승인·게시 라우팅 오류는 최초 결과를 보존한 다음 수정했다. 수정 후 점수로 최초 평가를 덮어쓰지 않았다. 새 RAG 표현의 검색 실패는 남겨 두었다.
- **MCP·Skill:** 읽기 전용 도구 6개, 버전별 프롬프트 리소스, 검토 Skill, 복수 인용의 원문·페이지 재조회까지 실제 SDK 연결을 확인했다.
- **DB·수집:** 원자적 배치·커서·버전 갱신, FTS5, 매개변수 SQL, 키셋 조회, 버전·중복 집계를 구현했다. 5천 건 결과는 합성 자료 실험이다.
- **검수:** Python 테스트 319개 통과, 실제 API·MCP 검사 14개와 금융 화면 연동 검사 6개 통과. 무료 로컬 모델만 사용했다.

## 아직 해결하지 않은 일과 우선순위

| 우선순위 | 남은 문제 | 다음 검증 기준 |
| --- | --- | --- |
| 1 | 문헌을 맞혀도 정답 근거 문장을 놓침 | SciFact의 관찰한 실패를 개발 회귀로 옮기고, 새 외부 표본에서 복수 구간의 근거 집합 포함률 평가 |
| 2 | RAG의 per-token/per-sequence 같은 새 표현에서 초록 기반 문서 후보를 잘못 좁힘 | 본문을 문서 후보 생성에도 반영하고, 새 사전 고정 문항에서 후보 recall·최종 문헌·인용을 분리 측정 |
| 3 | 실제 서비스 첫 요청이 오프라인 평가보다 느림 | 동시 보유 모델 메모리·준비·prefix·prefill을 분리해 반복 측정하고, 첫 요청·캐시 요청을 따로 보고 |
| 4 | 본문이 두 편·첫 3페이지에 한정됨 | 섹션별 추출·참고문헌/선행 연구 구분, 원문 변동·추출 실패·페이지 연결 검사 |
| 5 | 평가 범위가 작음 | SciFact의 SUPPORT 외 CONTRADICT/NEI, 금융·한국어의 외부 주석, 사람의 의미 정확도 검토 확대 |
| 6 | 분산·대규모 운영 미검증 | 실제 corpus 규모를 늘려 SQL·임베딩·후보 검색·큐 병목을 측정한 뒤 PostgreSQL/ANN 도입 결정 |

기존 내부 문항은 이미 관찰했으므로 새 개선의 독립 평가로 반복 사용하지 않는다. 사전 고정 12개도 실행 후 관찰한 자료가 됐다. 외부 주석 표본은 200문서·10개 주장으로, 전체 SciFact나 금융권 운영 정확도 수치가 아니다. 원문 위치 일치만으로 의미적 지지나 사실의 진실성이 증명되지 않는다.

이번 오프라인 회귀에서 두 누락 문항은 7.86초·5.31초였지만, 새 서비스 서버의 첫 g3 요청은 40.55초, 반복은 3.48초, v4는 24.06초였다. 서버 시작 시간은 별도다. 오프라인 수치를 서비스 지연으로 포장하지 않는다. 과거 284초 기록의 단일 원인도 로그가 부족해 확정하지 않았다.

11월 8일 제출 전에는 새 기술을 계속 늘리기보다 재현 가능한 시연·역할 설명·실제 측정값·남은 실패를 1쪽에 정리하는 일을 우선한다.

## 면접에서 설명할 핵심

> 채팅으로 금융 화면을 만드는 서비스에서 모델의 제안과 서버의 실행 책임을 분리했습니다. 문헌 검색을 다국어 검색·본문 후보 압축·인용별 슬롯 검증으로 확장하고, 문서 버전과 원문 위치는 서버가 확인합니다. 내부 회귀만으로 평가를 끝내지 않고 사전 고정 문항과 외부 연구자가 주석한 SciFact 표본으로 검증했습니다. 문헌 선택과 근거 문장 선택의 성능 차이, 실제 서버와 오프라인 지연 차이도 함께 기록했습니다.

**3번**에는 문헌 탐색·지식 정제·도구와 Skill·평가 자동화, **9번**에는 추론 준비·prefill·후보 압축·캐시와 자원 계측, **금융권·대기업 백엔드**에는 상태·트랜잭션·재개·DB 조회·버전 검증의 책임 분리로 연결한다. 수상 당시 구현과 이후 개인 확장을 구분하며 분산 학습이나 은행 운영 시스템을 구현한 것으로 확대하지 않는다.
