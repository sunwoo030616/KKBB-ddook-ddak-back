# 개발 현황과 다음 작업

## 이번에 끝낸 일

- **지연 계측:** 큐 대기·시스템 prefix·출력 규칙·첫 토큰·prefill·생성을 분리했다. 예전 284초 기록의 단일 원인은 확정하지 않았고, 실제 관찰과 추정을 구분했다.
- **검색·검증:** 원문 다국어 검색, 영어 전용 경로, 명시 조건, 저자 주장 문맥과 선택적 LLM 검증을 연결했다. 매번 두 번 생성하던 경로를 바꿨다.
- **검증 계약:** 프롬프트 v1·v2·v3와 해시, 후보별 허용 슬롯·지원 목록, 서버의 순위 선택과 출처 검증을 분리했다.
- **MCP·Skill:** 읽기 전용 도구 6개, 프롬프트 리소스와 검토 지침, 문헌 검토 Skill을 만들고 실제 stdio 및 로컬 AI 연결을 검사했다.
- **DB·파이프라인:** 묶음 버전 조회, 원자적 수집·색인·커서, FTS5, 키셋 페이지, 종류·버전·중복 집계를 구현했다.
- **README:** 서비스 흐름, 검증 자료, 실행 경로를 표·도식·접힌 과거 기록으로 정리했다.

수치는 [최신 병목 분석과 결과](문헌검색_병목분석_플랫폼개선.md), 실행은 [MCP·Skill·파이프라인 안내](MCP_Skill_수집파이프라인_실행.md), 면접 질문은 [백엔드 문답](백엔드_면접_질문과답변.md)을 참고한다. 최신 결과와 이전 개인 확장 기록, 수상 당시 구현을 혼합하지 않는다.

## 아직 해결하지 않은 일

1. 긴 문장의 저자 주장과 Wikipedia 같은 명시 조건을 짧은 인용 안에 함께 보존하는 경우 일부 문헌이 누락된다.
2. 초록에 없는 세부 알고리즘·측정값은 본문 근거가 필요하다. 기대 문헌 ID가 있다는 이유만으로 해당 주장을 뒷받침한다고 처리하지 않는다.
3. 24개 진단 문항과 추가 guard는 개발자가 만든 내부 자료이며, 개선 과정에서 관찰했다. 별도 사람의 독립 평가와 넓은 한국어 분포 검증이 필요하다.
4. 현재 별칭·저자 주장 추출은 규칙 기반 휴리스틱이다. 부정 표현·복잡한 비교·인용된 선행 연구를 모두 이해하는 담화 분석기가 아니다.
5. 대형 분산 수집·ANN 검색·다중 서버 서빙·금융 운영 부하는 검증하지 않았다.

## 면접에서 설명할 핵심

> 채팅으로 금융 화면을 만드는 서비스의 지식 처리 경로를 확장했습니다. 생성 모델 호출을 줄이는 것만으로는 기술 용어 손실이 생겨, 원문 다국어 검색과 불확실한 후보만 검증하는 구조를 비교했습니다. 배경 설명과 저자 주장을 구분하고 출처·인용·버전은 서버가 검사합니다. MCP 도구와 검토 Skill, 수집의 원자적 재개, 매개변수 SQL과 색인까지 연결하고 실패 사례를 함께 기록했습니다.

**3번**은 문헌 탐색·지식 정제·에이전트 도구·평가 자동화, **9번**은 단일 장비의 추론 준비·prefill·캐시·자원 경로 관측, **금융권·대기업 백엔드**는 상태·트랜잭션·재개·DB 조회·근거 버전의 책임 분리로 설명한다. 분산 학습이나 은행 운영 시스템을 구현한 것으로 확대하지 않는다.
