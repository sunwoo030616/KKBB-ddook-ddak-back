## 남은 상황형 실패

회귀 상황형은 74/100에서 72/100으로 2건 줄었다. 새 상황형도 JEV/GPT 모두 21/30이다. 전체 점수 상승을 상황 이해가 해결됐다는 뜻으로 해석하면 안 된다.

새 상황형 01의 일본 여행 준비 질문은 route_travel=0.66이 0.7에 못 미쳐 단일 메뉴 경로로 갔다. 숙박 메뉴 kb_menu_0604를 선택했고 환전·해외 QR·여행보험 묶음을 놓쳤다. 여행 여부를 한 임계값으로 막는 구조가 남은 실패 원인이다. 다른 실패에는 매출 현황·ATM 출금·입금 현황·오픈뱅킹 내역 등 복수 요청 일부 누락과 거래 내역 메뉴 혼동이 있다. 자동 라벨 자체의 독립 검수도 필요하다.

다음 개선 후보는 국가/여행 표현의 정책 라우팅 검증, 불확실한 상황의 복수 가설 검색, 요청별 누락 검사다. 이번 결과를 본 뒤 소스·정답·임계값을 바꾸어 같은 실험 점수를 올리지는 않았다.

## 한계와 재현

- 모델은 jev-1.14.0과 gpt-4o-mini-2024-07-18이다. GPT는 전체 585개 메뉴와 동일 v2 제품 정책을 받으며 프롬프트가 이전 실험과 달라 예전 GPT 점수와 직접 개선율로 비교하지 않는다.
- Choice confidence=0.6과 후보별 Noul probability=0.7은 다른 의미다. 평가 결과를 보고 임계값을 변경하지 않았다. 원문 분해 규칙은 한국어 접속 표현을 일부만 처리하므로 일반적인 의미 분해를 보장하지 않는다. 최대 3개 독립 업무를 지원한다.
- API 입력·출력·캐시 토큰은 원본 usage를 집계했다. 미제공은 0이 아니다. 제공자별 tokenizer와 usage 정의가 달라 입력+출력 합계를 동일 비용/연산량으로 환산하지 않는다. JEV 출력 토큰은 공개 단가에서 무료이며 로컬 E5 비용은 포함하지 않았다.
- 모든 시간에는 요청 경로의 로컬 처리·외부 호출이 포함되며 기동·컴파일·메뉴 임베딩 준비는 제외됐다. 실패·확인 요청·후보 확대 호출을 숨기지 않았다. 단일 실행의 네트워크/모델 변동성이 있다.
- 개발 사례는 이미 본 12개이며 개발 결과는 본 평가 점수나 토큰에 합치지 않았다. 회귀 300개는 학습용으로 노출된 평가이고, 추가 100개도 합성 라벨·공유 의도이므로 실사용 정확도 보장이 아니다.
- 기존 /api/menus/select와 9종 위젯 화면은 수정하지 않았다. 새 메뉴 추천 API와 실제 화면/거래 연결은 별개다. 원격 게시 없이 로컬 결과를 보존한다.
