# 문헌 검색 병목 분석과 플랫폼 개선

> 이 문서는 이전 단계 기록이다. 현재 본문·복수 인용 및 분리 평가 결과는 [최신 보고서](본문_복수인용_분리평가_결과.md)를 참고한다.

깨비뚝딱의 채팅 → 금융 위젯 화면 구성을 유지하며, 내부 문헌 검색·검증·도구 인터페이스·수집 및 DB 조회를 확장했다. 무료 로컬 모델만 사용했고, 아래 값은 실행 보고서에서 읽었다. 수상 당시 구현과 이후 개인 확장을 구분한다.

## 284초 기록과 실제 병목

이전 정상 문항 h4의 서버 처리 기록은 283.76초였다. 당시 보고서에는 단계별 추적이 없어 그 한 번의 지연을 특정 원인 하나로 확정할 수 없다. 새 계측으로 같은 기존 경로를 분리 측정했다.

- 기존 서버 재요청: 약 22.62초. 질의 생성 약 18.53초, 마지막 근거 선택 약 3.09초였다.
- 새 프로세스의 기존 경로: 첫 요청 13.42초, 다음 요청 4.43초. 첫 요청의 시스템 prefix 준비 약 4.08초, 구조화 규칙 준비 약 2.72초를 확인했다.
- 첫 프로파일에는 major page fault 629회, 다음 요청에는 0회가 기록됐다. 준비·메모리 페이지 영향과 일치하는 관찰이며, 과거 284초의 독립 원인을 증명한 값은 아니다.
- 일반 검색보다 생성 호출과 prefill 준비가 주요 경로였으므로 질의 생성과 최종 선택을 매번 모두 호출하는 구조를 바꿨다.

## 바꾼 검색·검증 경로

1. 한국어를 영어로 재작성하지 않고 원래 요청으로 작은 다국어 재평가 모델을 호출한다. 영어는 영어 전용 모델을 사용한다.
2. 명시한 도메인·위치·장치·토큰 조건을 출처와 대조한다. 검토한 제한적 별칭 규칙이며 범용 의미 분석이나 entailment 판정이 아니다.
3. 방법을 묻는 요청은 저자 주장 문맥을 우선한다. 논문이 배경에서 소개한 다른 방법을 그 논문의 기여로 오인하지 않도록 인용 구간과 주장 구간을 구분한다.
4. 충분한 순위 차이와 구절 점수가 있으면 생성 모델을 건너뛴다. 불확실한 과제들은 한 번의 Qwen3-4B 검증으로 묶는다.
5. 모델은 허용된 후보별 지원 여부만 반환하고 서버가 지원 후보 사이의 검색 순위를 유지한다. 실제 출처·URL·해시·인용 위치는 서버가 붙인다.
6. 후보 수·본문 길이·출력 토큰을 제한하고, 동시 문헌 요청은 대기열에 쌓는 대신 429로 반환한다. 조회 중 문서 버전이 바뀌면 결과를 비운다.

현재 모델: `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`(CPU 다국어), `cross-encoder/ms-marco-MiniLM-L6-v2`(CPU 영어), `Qwen3-4B-4bit`(불확실한 경우 검증). 새 다국어 모델은 공식 체크포인트의 리비전·해시를 고정해 준비하며 요청 중 다운로드하지 않는다.

전용 번역 모델은 기술 용어 손실 때문에 기본 경로로 채택하지 않았다. 큰 BGE의 CPU int8 경로도 로컬 지연이 커 채택하지 않았다. 짧은 질의만으로 처리한 초기 프로토타입은 품질이 낮아 실험 옵션으로 남겼다.

첫 HTTP 요청에는 새 문헌 모델 자원 준비를 포함했다. 서버 프로세스 시작 시간은 별도로 기록한다. 반복 값은 캐시 결과이며 새로운 문항의 추론 성능으로 제시하지 않는다. 실행 조건이 달라 속도 차이를 단일 파라미터의 독립적인 효과나 운영 SLA로 주장하지 않는다.

## MCP·Skill·프롬프트 구조

- 공식 MCP SDK의 stdio 초기화·도구 탐색·검색·인용 조회를 실제 검증했다. 읽기 전용 도구 6개를 제공한다.
- 검색, 키셋 목록, 현재 버전 인용, 신경 검색, 검토 상태, 통계를 분리했다. 승인·발행·임의 SQL 실행 도구는 제공하지 않는다.
- 실제 MCP → 로컬 AI API → DB 원문 재검증 연결도 통과했다. 서버의 현재 버전 플래그만 믿지 않고 MCP에서 해시와 인용을 다시 읽는다.
- `data/prompts/`에 지침 버전과 내용 해시를 보관하고, 후보별 출력 스키마와 허용 슬롯을 서버가 고정한다. 프롬프트 v1·v2·v3 실험을 구분했다.
- `.agents/skills/kkbb-literature-review/SKILL.md`는 도구 선택·현재 인용 검토·누락 표시를 규정하며 검증기를 통과했다. 저장소의 Skill과 MCP 서버 소스이며, 사용 중인 모든 클라이언트에 자동 등록한 것은 아니다.

## 수집·DB·분석 파이프라인

- JSONL을 제한된 레코드·배치 크기로 읽는다. 데이터 파일 해시·바이트 위치·행·리비전으로 재개를 관리한다.
- 문서 버전, FTS5 색인과 재개 위치를 한 SQLite 트랜잭션에서 커밋한다. 중간 오류는 함께 롤백하며 동시 커서 충돌도 검사한다.
- 기존 버전 조회를 묶음으로 처리하고 UPSERT로 rowid를 유지한다. 갱신·복원·삭제에 맞춰 FTS 색인을 동기화한다.
- 문서 종류와 ID의 복합 표현식 색인, 키셋 페이지, 매개변수 SQL, 제한된 FTS 질의를 구현했다. 통계는 한 읽기 스냅샷에서 종류·문자 수·버전·중복 표본을 집계한다.
- 합성 5,000건, 배치 200건: 첫 수집 0.257초, 기존 버전 조회 25회. 한 문서 변경 시 변경 1건·재사용 4,999건을 확인했다.
- 위 값은 로컬 합성 실험이다. 실제 자료는 초록 30편·금융 안내 26개이며, 분산 수집·은행 운영 TPS·ANN 대규모 검색을 구현했다고 주장하지 않는다.

## 검수와 직무 연결

실제 문헌 API 10개 검사, 금융 화면 API 6개 검사, MCP AI 연결 5개 검사가 통과했다. 기준일별 금융 근거, 중복 계획의 생성 호출 0, 새 화면 세션과 검토 대기 상태 보존을 확인했다.
3번에는 문헌 탐색·지식 정제·도구형 에이전트·검증 자동화를 연결한다. 9번에는 단일 Mac의 prefill·첫 토큰·대기·규칙 준비·자원 경로 관측을 설명한다. 금융권·대기업 백엔드에는 트랜잭션 경계, 재개 커서, 매개변수 쿼리, 색인, 버전 무효화와 도구 권한 경계를 설명한다.

재현: `scripts/evaluate_ranked_literature.py`, `scripts/profile_literature_request.py`, `scripts/verify_literature_platform.py`, `scripts/benchmark_knowledge_pipeline.py`, `scripts/verify_knowledge_mcp.py`. 모델과 원문은 로컬 `var/`에 보관한다.

근거 보고서: `reports/literature-platform-final.json`, `reports/literature-platform-api.json`, `reports/literature-bottleneck.json`, `reports/knowledge-pipeline-benchmark.json`, `reports/knowledge-mcp-live.json`, `reports/knowledge-mcp-stdio.json`.
